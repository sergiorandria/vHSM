# Fabric configuration

This directory holds the Hyperledger Fabric configuration for vHSM's ledger
anchoring. It is split into two deployment styles:

## `docker/` — single-host Docker stack (development / CI)

The all-in-one, container-based network used for local development and CI:
orderer, peers, Fabric-CA, PostgreSQL and OpenLDAP all run as containers on
one host and talk over a Docker network. Everything is generated by
`docker/generate-network.sh` + `docker/enroll-network.sh` and brought up with
`docker/docker-compose.yaml`.

Start here for a quick local ledger: `docker/README.md`.

## `real-network/` — multi-host deployment (production-style)

Configuration **templates** for running the network across separate machines
(e.g. the orderer + Org1 on a local machine, Org2 on an internet-reachable
VM). Unlike `docker/`, nodes are deployed per-host with public DNS/IP
addressing, real TLS SANs, and cross-host gossip. The files are placeholders
(`<...>` / `CHANGE_ME`) to adapt to your topology — see
`real-network/README.md` and `real-network/topology.md`.

## Chaincode

The chaincode source (`signature_ledger/`, `template_chaincode/`) lives at
this level and is shared by both deployments. CCaaS build/deploy steps are in
`docker/NEW_CHAINCODE.md` and `docker/REBUILD_IMG.md`.

## Client wiring

How the vHSM C++ `LedgerClient` / Go REST API point at the network is
documented in `../../docs/FABRIC_CHAINCODE.md`.
